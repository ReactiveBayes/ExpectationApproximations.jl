How a backend is chosen

No single rule is best for every distribution: Gauss–Hermite suits a Gaussian, Gauss–Laguerre a Gamma, an exact sum a categorical. A model mixes them, so it needs a backend that chooses. This page explains how that choice is made, from the most explicit way to the most automatic.

using ExpectationApproximations, Distributions
import BayesBase
const EA = ExpectationApproximations

What a backend supports

A backend declares, on types, which distributions and integrands it handles: BayesBase.supports_expectation(backend, F, Q) is true when it computes $\mathbb{E}_q[f]$ for f::F and q::Q. Integrand type Any means "every integrand", which is what a quadrature declares, since a quadrature does not care what the function is.

(
    BayesBase.supports_expectation(EA.GaussHermite(8), Any, Normal{Float64}),
    BayesBase.supports_expectation(EA.GaussHermite(8), Any, Gamma{Float64}),
)
(true, false)

Because the declaration is on types, the compiler decides it: choosing a backend costs nothing at run time.

Routers: the first backend that supports it

BayesBase.ExpectationFirstOf(backends...) tries its backends in order and uses the first that supports the pair. EADefault is such a router, with one rule per family:

EADefault(n = 16) = ExpectationFirstOf(ExactSum(), GaussHermite(n), GaussLaguerre(n), GaussJacobi(n), QuantileLegendre(n))

BayesBase.which_expectation_backend shows the choice:

backend = EA.EADefault()
distributions = (Normal(0.0, 1.0), Gamma(2.0, 1.0), Beta(2.0, 3.0), Categorical([0.5, 0.5]), Weibull(2.0, 1.0))
[nameof(typeof(q)) => nameof(typeof(BayesBase.which_expectation_backend(backend, sin, q))) for q in distributions]
5-element Vector{Pair{Symbol, Symbol}}:
                :Normal => :GaussHermite
                 :Gamma => :GaussLaguerre
                  :Beta => :GaussJacobi
 :DiscreteNonParametric => :ExactSum
               :Weibull => :QuantileLegendre

The Weibull distribution has no rule of its own, so it goes to QuantileLegendre, the fallback for any continuous univariate distribution. A distribution none of them covers, a Poisson for one, has no backend, and an expectation under it throws BayesBase.UnsupportedExpectationError:

BayesBase.which_expectation_backend(backend, sin, Poisson(3.0)) === nothing
true

To change the choice, build your own router: put a more accurate rule first, or a closed form from another package before the quadratures.

accurate = BayesBase.ExpectationFirstOf(EA.GaussHermite(40), EA.EADefault())
BayesBase.which_expectation_backend(accurate, sin, Normal(0.0, 1.0))
GaussHermite(40)

The registry: a choice the session makes

A library that runs inference does not know which backends the user's session has loaded. BayesBase keeps a registry of backends, and BayesBase.ExpectationDynamicRouter() chooses among the registered ones when it is called. Loading this package registers the rules of EADefault, through register_backends!; a package with closed forms registers its own, and they come first where they are exact.

Choosing at run time costs microseconds per call and allocates. Wrapping the dynamic router in ExpectationFirstOf freezes the choice the registry makes now into a router the compiler resolves, as fast as EADefault():

frozen = BayesBase.ExpectationFirstOf(BayesBase.ExpectationDynamicRouter())
BayesBase.which_expectation_backend(frozen, sin, Gamma(2.0, 1.0))
ExpectationApproximations.GaussLaguerre(16)

This is how RxInfer's fallback schemes find a backend when the model names none.

ExpectationApproximations.EADefault — Function
EADefault(n = 16)

The default backend: a router that sends each distribution to the rule made for its family, with n points per dimension. It is

BayesBase.ExpectationFirstOf(ExactSum(), GaussHermite(n), GaussLaguerre(n), GaussJacobi(n), QuantileLegendre(n))

so the first backend that supports a distribution computes its expectations:

DistributionBackend
finite discrete (Categorical, Bernoulli, Binomial, …)ExactSum, exact
Normal, MvNormal, LogNormal, LogitNormal, TransformedGaussianGaussHermite
Gamma, ExponentialGaussLaguerre
BetaGaussJacobi
any other continuous univariate distributionQuantileLegendre

The choice is made from the types alone, so the compiler resolves it. A product of distributions, a BayesBase.FactorizedJoint, is routed component by component. A distribution none of them covers, such as a Poisson, is not supported, and BayesBase.expectation throws BayesBase.UnsupportedExpectationError.

julia> BayesBase.expectation(EA.EADefault(), x -> x^2, Gamma(2.0, 1.0)) ≈ 6.0
true

julia> BayesBase.which_expectation_backend(EA.EADefault(), log, Beta(2.0, 3.0)) isa EA.GaussJacobi
true

julia> BayesBase.which_expectation_backend(EA.EADefault(), log, Poisson(3.0)) === nothing
true

ExpectationApproximations.register_backends! — Function
register_backends!(; kwargs...)

Add the rules of EADefault, with 16 points, to a registry of backends for automatic choice, BayesBase's global one by default. A BayesBase.ExpectationDynamicRouter chooses among the registered backends when it is called; BayesBase.ExpectationFirstOf(ExpectationDynamicRouter()) freezes that choice into a router the compiler resolves. With only these rules registered, both choose as EADefault() does. A backend registered by another package comes before them where it is exact for a pair or has a higher priority. This is how a model that names no backend, such as RxInfer's fallback = LocalLaplace(), finds one.

  • QuantileLegendre, which takes any continuous univariate distribution, is registered with the lowest priority, -100, so that it is chosen only where no other rule applies.
  • The stochastic backends, MonteCarlo and SNIS, are not registered: they need a random number generator, and an automatic choice stays deterministic.

Called when the package loads; registering again changes nothing. The keywords are passed on to BayesBase.register_expectation_backend!: registry names another BayesBase.ExpectationBackendRegistry.
