Choosing a backend

Every backend trades accuracy, cost and generality. This page compares them, so that you can pick one when EADefault is not what you need.

using ExpectationApproximations, Distributions
import BayesBase
const EA = ExpectationApproximations
using SpecialFunctions: digamma
using Random: Xoshiro

All of them prepare a point set, allocate nothing when evaluated, and pass dual numbers through the integrand. Two limits matter in practice:

  • Dimension. Gauss–Hermite on a $d$-dimensional Gaussian is a tensor grid of $n^d$ points: 20 points per dimension is 400 points in two dimensions and 8000 in three. Sigma points grow linearly in $d$, at the price of exactness only up to degree 3 or 4.
  • Derivatives through shapes. The nodes of Gauss–Laguerre and Gauss–Jacobi depend on the shape of the Gamma or Beta, so ForwardDiff cannot differentiate through a shape parameter. It can differentiate through the scale of a Gamma.

Accuracy: an example

Take $x \sim \mathrm{Gamma}(2.5, 1)$ and two integrands with closed forms: the smooth $e^{-x}$, with $\mathbb{E}[e^{-x}] = 2^{-2.5}$, and $\log x$, with $\mathbb{E}[\log x] = \psi(2.5)$, which is singular at zero.

q = Gamma(2.5, 1.0)
deviation(backend, f, exact) = abs(BayesBase.expectation(backend, f, q) - exact)
smooth(backend) = deviation(backend, x -> exp(-x), 2.0^-2.5)
singular(backend) = deviation(backend, log, digamma(2.5))
for (name, backend) in (
        "GaussLaguerre(16)" => EA.GaussLaguerre(16),
        "GaussLaguerre(64)" => EA.GaussLaguerre(64),
        "QuantileLegendre(16)" => EA.QuantileLegendre(16),
        "QuantileLegendre(64)" => EA.QuantileLegendre(64),
        "MonteCarlo(10_000)" => EA.MonteCarlo(10_000, Xoshiro(1)),
    )
    println(rpad(name, 22), "smooth error ", round(smooth(backend); sigdigits = 2), "   singular error ", round(singular(backend); sigdigits = 2))
end
GaussLaguerre(16)     smooth error 3.8e-14   singular error 0.00066
GaussLaguerre(64)     smooth error 5.3e-16   singular error 2.2e-5
QuantileLegendre(16)  smooth error 6.7e-5   singular error 0.00071
QuantileLegendre(64)  smooth error 1.5e-6   singular error 4.9e-5
MonteCarlo(10_000)    smooth error 0.0018   singular error 0.019

Three lessons:

  • for a smooth integrand, the rule matched to the family, Gauss–Laguerre for a Gamma, converges far faster than the generic quantile rule, whose error decreases only algebraically;
  • a singularity, such as the logarithm's at zero, slows every rule down, matched or not, to an error near $10^{-3}$ at 16 points: where a closed form exists, it should win. A router can put a closed-form backend first, and an integrand that has one is then never integrated numerically;
  • every quadrature beats sampling by orders of magnitude at a fraction of the points, but sampling is the only one that works for any distribution in any dimension.

Quadrature for families

ExpectationApproximations.GaussHermite — Type
GaussHermite(n)

Gauss–Hermite quadrature with n points per dimension, for Gaussian distributions: a Normal, a tensor grid of nᵈ points for a d-dimensional MvNormal, and a LogNormal or LogitNormal through its Gaussian in unconstrained coordinates. The result is exact for polynomials up to degree 2n - 1 of the Gaussian variable; since integrands are not polynomials in general, the backend is not labelled ExpectationExact.

The points are typed from the distribution's parameters, so dual numbers pass through the parameters as well as the integrand. The points of a Gaussian whose mean is a static vector are static vectors.

source
ExpectationApproximations.GaussLaguerre — Type
GaussLaguerre(n)

Generalised Gauss–Laguerre quadrature with n points for a Gamma or an Exponential distribution: for a shape a, the rule of weight t^(a - 1) exp(-t), so the result is exact for polynomials up to degree 2n - 1 whatever the shape, below one included. The weights are normalised to one, so very large shapes work too.

The rule depends on the shape, so it is computed when the expectation is prepared, and dual numbers pass through the scale and the integrand but not through the shape.

source
ExpectationApproximations.GaussJacobi — Type
GaussJacobi(n)

Gauss–Jacobi quadrature with n points for a Beta distribution: for shapes a and b, the rule of weight (1 - t)^(b - 1) (1 + t)^(a - 1) mapped onto the unit interval, so the result is exact for polynomials up to degree 2n - 1. The weights are normalised to one.

The rule depends on the shapes, so it is computed when the expectation is prepared, and dual numbers pass through the integrand but not through the shapes.

source
ExpectationApproximations.QuantileLegendre — Type
QuantileLegendre(n)

Gauss–Legendre quadrature with n points in probability space, E_q[f] = ∫₀¹ f(Q(u)) du with Q the quantile function of q, for any continuous univariate distribution. A fallback for the distributions no other rule covers: a quantile function is rarely smooth at both ends, so the error decreases algebraically with n rather than exponentially.

source
ExpectationApproximations.ExactSum — Type
ExactSum()

The exact expectation over a finite support: a sum over every value, weighted by its probability. For Categorical and other DiscreteNonParametric distributions, Bernoulli, Binomial, DiscreteUniform, Dirac and PointMass. Labelled ExpectationExact.

source

Sampling

Sampling makes no assumption about smoothness and works in any dimension, but its error decreases only as $1/\sqrt{n}$ and its results are random. Use it for a distribution no quadrature covers, or as a reference.

ExpectationApproximations.MonteCarlo — Type
MonteCarlo(n, rng = nothing)

The average over n samples, drawn with rng when the expectation is prepared, for any distribution that can be sampled. Labelled ExpectationStochastic. Without a random number generator it refuses to run; BayesBase.with_expectation_rng provides one from above and never replaces one set here.

source
ExpectationApproximations.SNIS — Type
SNIS(proposal, n, rng = nothing)

Self-normalised importance sampling: n samples from proposal, weighted by the ratio of the target's density to the proposal's and normalised, for a target that can be evaluated but not sampled, such as an unnormalised product of a prior and messages. Labelled ExpectationStochastic; the random number generator comes from BayesBase.with_expectation_rng unless set here. The weights are computed in log space, and effective_sample_size tells how many samples they are worth.

source
ExpectationApproximations.effective_sample_size — Function
effective_sample_size(prepared::ExpectationPointSet)

1 / Σᵢ wᵢ² for normalised weights: the number of equally weighted samples that the weighted ones are worth, n when the proposal is the target and far fewer when it fits poorly.

source

Sigma points

Sigma points are few and deterministic: they match the first moments of a distribution rather than integrate it, so they suit smooth functions of Gaussians in several dimensions, as in nonlinear filtering. For a linear function they are exact:

A, b = [1.0 2.0; 0.0 1.0], [0.5, -1.0]
m, V = EA.mean_cov(EA.Unscented(), x -> A * x + b, MvNormal([1.0, 2.0], [1.0 0.3; 0.3 2.0]))
m ≈ A * [1.0, 2.0] + b, V ≈ A * [1.0 0.3; 0.3 2.0] * A'
(true, true)

The unscented transform's centre point has a covariance weight that differs from its mean weight. Its prepared form is therefore a SigmaPointSet rather than a plain point set, and its negative centre weight rules out products of distributions and tilted moments. The spherical-radial cubature has equal positive weights and none of these limits.

ExpectationApproximations.Unscented — Type
Unscented(; α = 1e-3, β = 2.0, κ = 0.0)

The unscented transform for Gaussian distributions: 2d + 1 sigma points, the mean and the mean plus and minus the columns of √(d + λ) L, with λ = α²(d + κ) - d and L the Cholesky factor of the covariance. Expectations are exact for polynomials up to degree 3.

The centre has a covariance weight that differs from its mean weight by 1 - α² + β, which mean_cov and mean_cov_cross apply; β = 2 is optimal for Gaussians. With the default α the centre weight is large and negative, so the transform does not support products of distributions, and tilted_mean_cov refuses it.

source
ExpectationApproximations.SigmaPointSet — Type
SigmaPointSet(points, weights, centre)

A prepared expectation over sigma points: a weighted sum with weights, the mean weights, whose first point, the centre, has a covariance weight larger by centre.

It is what BayesBase.prepare_expectation(Unscented(), q) returns, in place of a BayesBase.ExpectationPointSet: the unscented transform weighs the centre differently for means and for covariances, which a single set of weights cannot express. BayesBase.expectation uses the mean weights, and mean_cov and mean_cov_cross add the correction.

source
ExpectationApproximations.GenUnscented — Type
GenUnscented()

The generalised unscented transform: three points per dimension, with weights that match the mean, variance, skewness and kurtosis of the distribution, so that expectations are exact for polynomials up to degree 4. For any univariate distribution with a skewness and a kurtosis (a Gamma, a Beta, a Poisson), and for Gaussian vectors, along each axis of the Cholesky factor of the covariance.

source
ExpectationApproximations.SphericalRadialCubature — Type
SphericalRadialCubature()

The third-degree spherical-radial cubature rule for Gaussian distributions: 2d points, the mean plus and minus the columns of √d L, with equal positive weights; exact for polynomials up to degree 3.

source

ExponentialFamily's distributions

When ExponentialFamily is loaded, an extension adds its own types:

  • its univariate Gaussians, NormalMeanVariance, NormalMeanPrecision and NormalWeightedMeanPrecision, to GaussHermite, Unscented, GenUnscented and SphericalRadialCubature;
  • GammaShapeRate to GaussLaguerre.

Its multivariate Gaussians are Distributions' AbstractMvNormals, which the package covers without the extension. So EADefault handles the distributions RxInfer's rules produce.
