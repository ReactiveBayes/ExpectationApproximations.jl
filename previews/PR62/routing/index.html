How a backend is chosen

Each quadrature rule is made for one family of distributions: Gauss–Hermite for Gaussians, Gauss–Legendre in the logarithm for Gammas, an exact sum for categorical distributions. A model usually contains several families, so it needs a backend that chooses a rule for each distribution.

using ExpectationApproximations, Distributions
import BayesBase
const EA = ExpectationApproximations

What a backend supports

A backend declares, on types, which integrands and distributions it handles: BayesBase.supports_expectation(backend, F, Q) is true when it computes $\mathbb{E}_q[f]$ for f::F and q::Q. The integrand type Any means any integrand. A quadrature supports it, because a quadrature works the same way for every function.

(
    BayesBase.supports_expectation(EA.GaussHermite(8), Any, Normal{Float64}),
    BayesBase.supports_expectation(EA.GaussHermite(8), Any, Gamma{Float64}),
)
(true, false)

Because support is declared on types, the compiler resolves the choice of a backend, and the choice has no run-time cost.

Routers

BayesBase.ExpectationFirstOf(backends...) tries its backends in order and uses the first one that supports the integrand and the distribution. EADefault is such a router, with one rule per family:

EADefault(n = 16) = ExpectationFirstOf(ExactSum(), GaussHermite(n), UnconstrainedLegendre(), QuantileLegendre(n))

BayesBase.which_expectation_backend shows the choice:

backend = EA.EADefault()
distributions = (Normal(0.0, 1.0), Gamma(2.0, 1.0), Beta(2.0, 3.0), Categorical([0.5, 0.5]), Weibull(2.0, 1.0))
[nameof(typeof(q)) => nameof(typeof(BayesBase.which_expectation_backend(backend, sin, q))) for q in distributions]
5-element Vector{Pair{Symbol, Symbol}}:
                :Normal => :GaussHermite
                 :Gamma => :UnconstrainedLegendre
                  :Beta => :UnconstrainedLegendre
 :DiscreteNonParametric => :ExactSum
               :Weibull => :UnconstrainedLegendre

The Weibull distribution has no rule of its own, so it goes to QuantileLegendre, the fallback for continuous univariate distributions. A distribution that none of the rules supports, such as Poisson, has no backend, and an expectation under it throws BayesBase.UnsupportedExpectationError:

BayesBase.which_expectation_backend(backend, sin, Poisson(3.0)) === nothing
true

To change the choice, build another router. For example, put a more accurate rule first, or a closed form from another package before the quadratures:

accurate = BayesBase.ExpectationFirstOf(EA.GaussHermite(40), EA.EADefault())
BayesBase.which_expectation_backend(accurate, sin, Normal(0.0, 1.0))
GaussHermite(40)

The registry

A library that runs inference does not know which backend packages the user has loaded. BayesBase therefore keeps a registry of backends, and BayesBase.ExpectationDynamicRouter() chooses among the registered backends when it is called. Loading this package registers the rules of EADefault through register_backends!. A package with closed forms registers its own backends, and they are chosen first where they are exact.

The dynamic router chooses at run time, which takes microseconds per call and allocates. Wrapping it in ExpectationFirstOf fixes the current choice of the registry in a router that the compiler resolves, which is as fast as EADefault():

frozen = BayesBase.ExpectationFirstOf(BayesBase.ExpectationDynamicRouter())
BayesBase.which_expectation_backend(frozen, sin, Gamma(2.0, 1.0))
UnconstrainedLegendre(8)

RxInfer's fallback schemes use this to find a backend when the model does not specify one.

ExpectationApproximations.EADefault — Function
EADefault(n = 16)

The default backend: a router that sends each distribution to the rule made for its family, with n points per dimension for a Gaussian and for the quantile rule. The rule in unconstrained coordinates keeps its own default, 8 points per panel. It is

BayesBase.ExpectationFirstOf(ExactSum(), GaussHermite(n), UnconstrainedLegendre(), QuantileLegendre(n))

so the first backend that supports a distribution computes its expectations:

DistributionBackend
finite discrete (Categorical, Bernoulli, Binomial, …)ExactSum, exact
Normal, MvNormal, LogNormal, LogitNormal, TransformedGaussianGaussHermite, with at most 10 000 points in many dimensions
Gamma, Exponential, Chisq, Erlang, InverseGamma, Weibull, BetaUnconstrainedLegendre, in log x or logit x
any other continuous univariate distribution with a quantile functionQuantileLegendre

Gauss–Laguerre and Gauss–Jacobi are exact for polynomials in x, but integrands such as log x are singular at the boundary, where they converge slowly: with 16 points, E[log x] under Gamma(0.1, 1) is off by 6.1. GaussLaguerre and GaussJacobi remain available to choose explicitly.

The choice is made from the types alone, so the compiler resolves it. A product of distributions, a BayesBase.FactorizedJoint, is routed component by component. A distribution none of them covers, such as a Poisson, is not supported, and BayesBase.expectation throws BayesBase.UnsupportedExpectationError.

julia> BayesBase.expectation(EA.EADefault(), x -> x^2, Gamma(2.0, 1.0)) ≈ 6.0
true

julia> BayesBase.which_expectation_backend(EA.EADefault(), log, Beta(2.0, 3.0)) isa EA.UnconstrainedLegendre
true

julia> BayesBase.which_expectation_backend(EA.EADefault(), log, Poisson(3.0)) === nothing
true

ExpectationApproximations.register_backends! — Function
register_backends!(; kwargs...)

Add the rules of EADefault, with 16 points, to a registry of backends for automatic choice, by default the global registry of BayesBase. A BayesBase.ExpectationDynamicRouter chooses among the registered backends when it is called, and BayesBase.ExpectationFirstOf(ExpectationDynamicRouter()) fixes that choice in a router that the compiler resolves. With only these rules registered, both choose as EADefault() does. A backend registered by another package is chosen before them where it is exact for the integrand and the distribution, or where it has a higher priority. A model that specifies no backend, such as one run with RxInfer's fallback = LocalLaplace(), finds one this way.

No two of these rules cover the same family, so the choice among them never depends on the order in which backends are registered or on their names. QuantileLegendre, which supports any continuous univariate distribution with a quantile function, is registered with a priority 100 below the others, so that it is chosen only where no other rule applies. GaussLaguerre and GaussJacobi are not registered. The stochastic backends, MonteCarlo and SNIS, are not registered: they need a random number generator, and the automatic choice is kept deterministic.

The package calls this function when it loads; registering again changes nothing. The keywords are passed on to BayesBase.register_expectation_backend!; for example, registry selects another BayesBase.ExpectationBackendRegistry.
