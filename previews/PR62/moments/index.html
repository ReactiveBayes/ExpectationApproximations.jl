Moments through functions

For a Gaussian $x$ and a nonlinear function $y = f(x)$, Gaussian message passing needs the mean and covariance of $y$ and the cross-covariance of $x$ and $y$. These moments define a Gaussian message through a nonlinear node, as in the extended, unscented and cubature Kalman filters. mean_cov and mean_cov_cross compute them with any backend, and linearize computes the first-order expansion of $f$.

using ExpectationApproximations, Distributions
import BayesBase
const EA = ExpectationApproximations

The moments of $f(x)$

mean_cov(backend, f, q) returns $m = \mathbb{E}[f(x)]$ and $V = \mathbb{E}[(f(x) - m)(f(x) - m)^\top]$ for $x \sim q$. These are the moments of a function of $x$; BayesBase.mean_cov(q) returns the moments of $q$ itself. For example, for the polar-to-Cartesian map, a common test case for nonlinear filters:

polar = MvNormal([1.0, π / 4], [0.01 0.0; 0.0 0.2])
tocartesian(x) = [x[1] * cos(x[2]), x[1] * sin(x[2])]
m, V = EA.mean_cov(EA.GaussHermite(10), tocartesian, polar)
([0.6398166741645537, 0.6398166741645539], [0.09563462346100908 -0.07085375329105986; -0.07085375329105986 0.09563462346100908])

The same call with SphericalRadialCubature() uses 4 points instead of 100, and Unscented() uses 5:

EA.mean_cov(EA.SphericalRadialCubature(), tocartesian, polar)[1], EA.mean_cov(EA.Unscented(), tocartesian, polar)[1]
([0.6387219221874735, 0.6387219221874735], [0.6363961054012179, 0.6363961054594256])

mean_cov_cross adds the cross-covariance $C = \mathbb{E}[(x - \mathbb{E}x)(f(x) - m)^\top]$, which a Kalman update needs to condition $x$ on an observation of $y$:

m, V, C = EA.mean_cov_cross(EA.GaussHermite(10), tocartesian, polar)
C
2×2 Matrix{Float64}:
  0.00639817  0.00639817
 -0.127963    0.127963

Tilted moments

Expectation propagation needs the moments of a Gaussian tilted by a factor, $q(x) e^{\log f(x)} / Z$. tilted_mean_cov(backend, logf, q) returns $\log Z$, the mean and the covariance. It works in log space, so that very small or very large factors do not underflow or overflow. For a Gaussian likelihood the result is close to the conjugate posterior. It is not exact, because the factor is not a polynomial in $x$:

prior = Normal(0.0, 2.0)
loglikelihood(x) = logpdf(Normal(x, 1.0), 1.5)
logZ, m, v = EA.tilted_mean_cov(EA.GaussHermite(20), loglikelihood, prior)
(logZ = logZ, m = m, v = v, exact_m = 1.5 * 4 / 5, exact_v = 4 / 5)
(logZ = -1.9490380467669461, m = 1.1986791956056566, v = 0.8050251574375915, exact_m = 1.2, exact_v = 0.8)

The points come from $q$, so the result is accurate only for a factor that is not much sharper than $q$. For a sharp factor, use moment_matching, which places the points on the tilted density itself; see Gaussian approximations of a density.

Linearisation

linearize(f, x) returns $A$ and $b$ with $f(x') \approx A x' + b$ near $x$, the first-order expansion used by the extended Kalman filter. It also takes several inputs and stacks them:

A, b = EA.linearize((x, y) -> x * y + sin(x), 1.0, 2.0)
(adjoint([2.5403023058681398, 1.0]), -1.6988313210602435)

Linearisation needs no quadrature and is exact for linear functions, but it ignores the curvature of $f$ over the spread of $x$. mean_cov and mean_cov_cross take the curvature into account.

ExpectationApproximations.mean_cov — Function
mean_cov(backend, f, q) -> (m, V)
mean_cov(prepared, f) -> (m, V)

The mean and covariance of the pushforward of q through f: m = E[f(x)] and V = E[(f(x) - m)(f(x) - m)ᵀ] for x ~ q; V is a variance for a scalar f. These are the moments of a function of x, whereas BayesBase.mean_cov(q) returns the moments of q itself. They are computed by backend, or by an expectation prepared once and used for many functions.

julia> m, V = EA.mean_cov(EA.GaussHermite(8), x -> 2x + 1, Normal(1.0, 3.0));

julia> m ≈ 3.0 && V ≈ 36.0
true

ExpectationApproximations.mean_cov_cross — Function
mean_cov_cross(backend, f, q) -> (m, V, C)
mean_cov_cross(prepared, f) -> (m, V, C)

mean_cov and the cross-covariance C = E[(x - E[x])(f(x) - m)ᵀ] between the input and the output: a scalar, a vector for a vector input and a scalar output, a row for a scalar input and a vector output, a matrix otherwise.

ExpectationApproximations.tilted_mean_cov — Function
tilted_mean_cov(backend, logf, q) -> (logZ, m, V)
tilted_mean_cov(prepared, logf) -> (logZ, m, V)

The moments of the tilted distribution q(x) exp(logf(x)) / Z, as in the moment-matching step of expectation propagation: the log-normaliser logZ = log E_q[exp(logf)], the mean and the covariance. The second form takes a point set prepared once for q, a BayesBase.ExpectationPointSet or a BayesBase.ExpectationProductPointSet. The computation is in log space, shifted by the largest log-density at a point, so extreme log-densities do not overflow or underflow. For a product of distributions of mixed kinds, the mean and covariance are tuples with one entry per component.

The backend must prepare a point set for q. The quadrature, sampling and exact-sum backends do, and a router uses the backend it chooses for q.

ExpectationApproximations.linearize — Function
linearize(f, x) -> (A, b)
linearize(f, x₁, x₂, ...) -> (A, b)

The first-order expansion f(x) ≈ A x + b at the point x, with derivatives from ForwardDiff, and b = f(x) - A x. Depending on the shapes of the input and the output, A is a derivative, a column, a gradient as a row, or a Jacobian. Several inputs, numbers or vectors, are linearised jointly, and A then acts on their concatenation.
